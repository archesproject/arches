### New Features

- Confirm support for Django 6.0 [#12584](https://github.com/archesproject/arches/pull/12584)
- Enable dynamic importing of TypeScript files [#12601](https://github.com/archesproject/arches/pull/12601)
- Move packages in arches-dev-dependencies repo into local peerDependencies [#12663](https://github.com/archesproject/arches/pull/12663)
- Move default configs from cards_x_nodes_x_widgets to node config [#12725](https://github.com/archesproject/arches/pull/12725)
- Add `--use_multiprocessing` (-mp) and `--max_subprocesses` (-mxp) options to the `etl` management command to control indexing parallelism, matching the `es` command [#PR](https://github.com/archesproject/arches/pull/PR)
- Extract sidenav into its own template for project-level customization [#12689](https://github.com/archesproject/arches/issues/12689)
- Datatypes can define their own copy logic when a resource or tile are cloned [#12706](https://github.com/archesproject/arches/pull/12706)
- During resource cloning, distinct resource_x_resource records are created for resource instance (list) nodes [#12715](https://github.com/archesproject/arches/pull/12715)
- Re-enable resource cloning in the resource editor and add copy-specify logic for edit-log display [#12749](https://github.com/archesproject/arches/pull/12749)
- Fix Photo Workbench save failure message [#12942](https://github.com/archesproject/arches/pull/12942)
- Upgraded rdflib to 7.6.0 and Python 3.14 is now supported [#12790](https://github.com/archesproject/arches/pull/12790)
- Add command to calculate descriptors independent of ES index [#12828](https://github.com/archesproject/arches/issues/12828)
- Add option to forgo indexing during bulkload cli commands [#12883](https://github.com/archesproject/arches/pull/12883)
- Ensure lifecycles are saved before related states[#12931] https://github.com/archesproject/arches/pull/12931
- Add method to filter resource queryset by permission [#12888](https://github.com/archesproject/arches/issues/12888)
- Add multi-card descriptor [#12829](https://github.com/archesproject/arches/pull/12829)
- Add Indonesian (`id`) UI locale [#12905](https://github.com/archesproject/arches/pull/12905)
- Bundle the `arches_querysets`, `arches_vue_components` and `arches_controlled_lists` applications into arches itself, under `arches.extensions`, so they version and release with arches and no longer need a separate `pip install`. - Fully migrate map rendering from Mapbox GL JS to MapLibre GL JS, and swap the map geocoder widget's default backend to OpenStreetMap Nominatim (no API key required) [#12913](https://github.com/archesproject/arches/issues/12913)
- Remove the default `satellite` basemap and its `mapbox-satellite` source, which relied on Mapbox's proprietary `mapbox://` tile protocol and rendered an empty basemap under MapLibre [#12913](https://github.com/archesproject/arches/issues/12913)

### Deprecations

- `createVueApplication`, `generateArchesURL`, `ArchesPreset`, and `DEFAULT_THEME` in `arches` are deprecated in favor of their equivalents in `arches-vue-components` [#12824](https://github.com/archesproject/arches/pull/12824)
- The top-level module paths `arches_querysets`, `arches_vue_components` and `arches_controlled_lists` are deprecated in favor of `arches.extensions.querysets`, `arches.extensions.vue_components` and `arches.extensions.controlled_lists`. Both spellings work in 8.2.0: a compatibility alias resolves the old paths — in Python imports and in the dotted paths Django reads out of settings — while raising a `DeprecationWarning`, and `arches.W002` flags any `INSTALLED_APPS` entry still using them. The alias is scheduled for removal in Arches 9.0, so update your imports and settings before then. See [Applications Bundled with Arches](https://arches.readthedocs.io/en/stable/developing/extension-applications/bundled-applications/) [#12933](https://github.com/archesproject/arches/pull/12933)

### Breaking changes

- The minimum supported version of Python is now 3.12.

- The `v3` migration management command is removed.

- The `FutureWarning` for missing `update_fields` in custom `update_or_create()` calls is removed. If you had `FutureWarning` in project tests on Arches 8.1, see the 8.1 release notes for a resolution.

- Bootstrap 3's JavaScript is no longer bundled; only its stylesheet is, vendored at `arches/app/media/css/vendor/bootstrap-3.4.1.css`. The modal, tab, dropdown and collapse plugins are reimplemented in `arches/app/media/js/bootstrap-behaviors/`, are installed automatically, and keep the `$(element).modal('show')` jQuery API, so existing call sites need no change.

    Tooltip and popover are not reimplemented: `$(element).tooltip()` and `$(element).popover()` are now no-ops rather than errors. Markup using `data-toggle="tooltip"` with `data-original-title` will silently stop showing tooltips; replace both attributes with a single `data-tooltip="..."` to use arches' CSS-only tooltip, which honors `data-placement="top"` and otherwise renders below the element.

    See [Upgrading an Arches application](#upgrading-an-arches-application) for the full list of what carries over and what does not, including which Bootstrap events are still emitted.

- The `datepicker` and `colorPicker` knockout bindings are now backed by Tempus Dominus 6 and a native `<input type="color">` respectively. Both keep their existing binding options, and the `format` and `viewMode` values stored in graph node configs are unchanged.

- Enabling `arches.extensions.querysets` overrides core's `file-list`, `concept`, `concept-list`, `resource-instance`, `resource-instance-list`, `node-value`, `string`, `url` and `geojson-feature-collection` datatypes throughout the application, not only the querysets ORM layer.

    The clearest difference is `file-list`. Core's `transform_value_for_tile()` creates a `File` record and a URL for every entry; the override deletes the records it just created for entries that arrived without a `file_id`, leaving `file_id` and `url` null so a later upload step can link the real file. Bulk imports are unaffected, because `bulk_import` in the call suppresses the reset.

    Projects generated on 8.2.0 enable this application by default. Existing projects are opt-in and keep core's datatypes until they add it to `INSTALLED_APPS`. See [Applications Bundled with Arches](https://arches.readthedocs.io/en/stable/developing/extension-applications/bundled-applications/).
- Map rendering now uses MapLibre GL JS instead of Mapbox GL JS ([#12913](https://github.com/archesproject/arches/issues/12913)):
    - The `MAPBOX_SPRITES` and `MAPBOX_GLYPHS` settings are renamed to `MAPLIBRE_SPRITES` and `MAPLIBRE_GLYPHS`. A data migration relabels existing installed values automatically; any custom URLs you configured are preserved. The default `MAPLIBRE_GLYPHS` now points at MapLibre's free public font server, and the default `MAPLIBRE_SPRITES` is empty (no public default sprite sheet is available).
    - `MAPBOX_API_KEY` is unchanged, since it still authenticates Mapbox's own Geocoding API service used by the built-in Mapbox geocoder widget, which is unrelated to the GL rendering library.
    - The map geocoder widget's default backend is now OpenStreetMap's free Nominatim service, so no API key is required out of the box. Projects wanting a different geocoding provider (e.g. Mapbox, MapTiler) can override `arches/app/media/js/utils/maplibre-geocoder-api.js` at the project level (also update its `geocoderAttribution` export to match). Per [Nominatim's usage policy](https://operations.osmfoundation.org/policies/nominatim/), the map's attribution control now credits Nominatim; high-traffic projects should self-host Nominatim or switch providers.
    - Projects that directly imported `bindings/mapbox-gl`, used the `mapboxgl` knockout binding handler, or relied on `.mapboxgl-*` CSS classes must switch to `bindings/maplibre-gl`, the `maplibregl` binding handler, and `.maplibregl-*` classes, respectively. `@mapbox/mapbox-gl-draw` (drawing tools) is unaffected, as it has no dependency on mapbox-gl.

### Upgrading Arches

1. You must be upgraded to at least version 8.1.0 before proceeding. 

2. Upgrade to Arches 8.2.0
    ```
    pip install --upgrade arches==8.2.0
    ```

### Upgrading an Arches project

1. Follow instructions to upgrade each Arches project database to Postgres 16 or higher. https://www.postgresql.org/docs/current/upgrading.html

1. In pyproject.toml, make these updates:
    - Update `requires-python` to `">=3.12"`
    - Remove `"Programming Language :: Python :: 3.11"`
    - Remove `"Framework :: Django :: 5.2"`
    - Add `"Programming Language :: Python :: 3.14"`
    - Add `"Framework :: Django :: 6.0"`

1. Update ``EMAIL*`` settings to ``MAILERS`` following the [migration guide](https://docs.djangoproject.com/en/6.1/howto/mailers-migration/).

1. Optionally update settings to set `SECURE_REFERRER_POLICY = 'strict-origin-when-cross-origin'` to ensure referrer headers (strictly the origin) are sent in cross-origin HTTP requests. Resolves 404 errors from some map tile requests. For more details see [#12874](https://github.com/archesproject/arches/issues/12874).

1. If your project's `settings.py` overrides `MAPBOX_SPRITES` or `MAPBOX_GLYPHS`, rename them to `MAPLIBRE_SPRITES` and `MAPLIBRE_GLYPHS`. If your project imports `bindings/mapbox-gl` or references `.mapboxgl-*` CSS classes, update these to `bindings/maplibre-gl` and `.maplibregl-*` respectively.

1. Apply automatic updates:

    ```
    python manage.py updateproject
    ```

1. `updateproject` does not touch your project's templates. Because Arches no longer depends on Bootstrap 3, update `<project_name>/templates/index.htm` by hand.

    Replace the CDN stylesheet links with local equivalents:

    ```diff
    - <link rel="stylesheet" type="text/css" href="//fonts.googleapis.com/css?family=Open+Sans:400,300,600&amp;subset=cyrillic,latin">
    - <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/twitter-bootstrap/3.3.2/css/bootstrap.min.css">
    - <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/font-awesome/4.2.0/css/font-awesome.min.css">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'fonts/openSans.css' %}">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'css/vendor/bootstrap-3.4.1.css' %}">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'node_modules/font-awesome/css/font-awesome.min.css' %}">
    ```

    Remove the Bootstrap script tag, which will 404 once `bootstrap` leaves `node_modules`:

    ```diff
    - <script src="{% webpack_static 'node_modules/bootstrap/dist/js/bootstrap.min.js' %}"></script>
    ```

    And load the replacement behaviours alongside the other bundles, so the landing page's navbar toggle keeps working:

    ```diff
      <!-- Custom Scripts -->
    + {% render_bundle 'bootstrap-behaviors/index' %}
      {% render_bundle 'bindings/chosen' %}
    ```

    If you have not customized `index.htm`, you can instead copy the current version from `arches/install/arches-templates/project_name/templates/index.htm`.

1. In package.json:

    Remove "arches-dev-dependencies" from "devDependencies" and run:


        ```bash
        rm -r node_modules; rm package-lock.json
        npm install
        ```

1. Migrate database:

    ```bash
    python manage.py migrate
    ```

1. Optionally enable the Arches applications now bundled with arches: `arches_querysets`, `arches_vue_components` and `arches_controlled_lists`. They ship inside the arches distribution as of 8.2.0, so there is nothing to `pip install` and nothing to add to `pyproject.toml`. A project generated on 8.2.0 already has everything below. Skip any application you do not want, along with the settings that reference it. Full reference: [Applications Bundled with Arches](https://arches.readthedocs.io/en/stable/developing/extension-applications/bundled-applications/).

    If you were already running any of these as separately installed packages, uninstall them first and remove them from `pyproject.toml`, so the bundled copies are the ones that load:

    ```bash
    pip uninstall arches-querysets arches-vue-components arches-controlled-lists
    ```

    Their app labels, database tables and migration history are unchanged by the move, so there is no data migration to run, and imports or settings entries still naming the old top-level module paths keep working — see Deprecations above. Otherwise the steps below are the same as a first-time install.

    In `settings.py`, add these to `INSTALLED_APPS`. They must come after your own project app and before `"arches"`: Django resolves management commands by walking `INSTALLED_APPS` in reverse, and `arches_vue_components` overrides `validate`. `controlled_lists` must follow `querysets`, against which it registers a serializer at startup.

    ```python
    INSTALLED_APPS = (
        ...
        "django.contrib.postgres",  # required by controlled_lists, whose ListItem uses ExclusionConstraint
        "rest_framework",           # required by the querysets REST layer
        ...
        "<project_name>",
        "arches.extensions.querysets",
        "arches.extensions.vue_components",
        "arches.extensions.controlled_lists",
    )
    ```

    Be sure caches are added for querysets:

    ```python
    CACHES = {
        ...
        'querysets_concepts': {
            'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
            'LOCATION': 'querysets_concepts_cache',
            'TIMEOUT': 86400,  # one day in seconds
            'OPTIONS': {'MAX_ENTRIES': 1000},
        },
        'querysets_resource_instances': {
            'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
            'LOCATION': 'querysets_resource_instances_cache',
            'TIMEOUT': 86400,  # one day in seconds
            'OPTIONS': {'MAX_ENTRIES': 1000},
        },
    }
    ```

    For `controlled_lists`, register the reference index and make its values searchable. `REFERENCES_INDEX_NAME` is inherited from `arches.settings`; the index itself stays project-declared so that projects which do not enable the application are not made to build it.

    ```python
    ELASTICSEARCH_CUSTOM_INDEXES = [
        {
            'module': 'arches.extensions.controlled_lists.search_indexes.reference_index.ReferenceIndex',
            'name': REFERENCES_INDEX_NAME,
            'should_update_asynchronously': True,
        },
    ]

    TERM_SEARCH_TYPES = list(TERM_SEARCH_TYPES) + [
        {
            'type': 'reference',
            'label': _('References'),
            'key': REFERENCES_INDEX_NAME,
            'module': 'arches.extensions.controlled_lists.search_indexes.reference_index.ReferenceIndex',
        },
    ]

    ES_MAPPING_MODIFIER_CLASSES = [
        "arches.extensions.controlled_lists.search.references_es_mapping_modifier.ReferencesEsMappingModifier",
    ]
    ```

    In your project's `urls.py`, mount the applications' routes ahead of core's:

    ```python
    urlpatterns.append(path('', include('arches.extensions.querysets.urls')))
    urlpatterns.append(path('', include('arches.extensions.vue_components.urls')))
    urlpatterns.append(path('', include('arches.extensions.controlled_lists.urls')))
    ```

    Then migrate, create the reference index, and rebuild the frontend:

    ```bash
    python manage.py migrate
    python manage.py es setup_indexes -n references
    npm install
    npm run build_development
    ```

1. Validate your graphs verify all default values are valid:

    ```bash
    python manage.py validate --verbosity=2
    ```

### Upgrading an Arches application

Arches applications that ship their own templates or legacy JavaScript need the same
`index.htm` edits described above, plus a review of any Bootstrap 3 usage of their own.

1. If your application ships its own `index.htm`, apply the changes from the project
   section above. Older copies also carry a RequireJS-style block that resolves
   `bootstrap` to a path that no longer exists:

    ```diff
      paths: {
    -     'bootstrap': "{% webpack_static 'node_modules/bootstrap/dist/js/bootstrap.min' %}",
      },
      shim: {
    -     'bootstrap': {
    -         deps: ['jquery', 'jquery-ui']
    -     },
      }
      require([
          'jquery',
          'knockout',
    -     'bootstrap',
      ], function() {});
    ```

    Load `{% render_bundle 'bootstrap-behaviors/index' %}` instead. The bundle installs
    itself on import, so nothing else is required to wire it up.

2. Remove `bootstrap`, `bootstrap-colorpicker`, `eonasdan-bootstrap-datetimepicker` and
   `knockstrap` from your application's `package.json` if it declares them directly, along
   with any `nodeModulesPaths` entries pointing into those packages. If your SCSS imports
   `node_modules/bootstrap/dist/css/bootstrap.min.css` directly, point it at
   `css/vendor/bootstrap-3.4.1.css` instead. Every Bootstrap 3 class is still available:
   only the JavaScript was dropped.

3. Most markup driven by `data-*` attributes keeps working untouched, because the
   replacement behaviours bind the same attributes on `document`:

    | Markup | Status |
    | --- | --- |
    | `data-toggle="modal"`, `data-dismiss="modal"` | works unchanged |
    | `data-toggle="tab"`, `data-toggle="pill"` | works unchanged |
    | `data-toggle="dropdown"` | works unchanged |
    | `data-toggle="collapse"` | works unchanged |
    | `data-toggle="tooltip"` + `data-original-title` | **must be changed** to `data-tooltip="..."` |
    | `data-toggle="buttons"` | **no replacement**; the vendored stylesheet still carries its selectors, but the radio/checkbox toggling behaviour is gone |
    | `data-dismiss="alert"` | **no replacement**; Bootstrap's alert plugin was not reimplemented |
    | `data-container`, `data-placement="auto"` | no longer meaningful, safe to delete |

    Arches' own `data-dismiss="alert"` button in `login.htm` removes its alert with an
    inline `onclick` and is unaffected; the same approach works for applications that
    relied on the plugin.

    `data-tooltip` draws the tooltip with the element's `::after`, so it is safe on icon
    elements, whose glyph comes from `::before`. Do not put it on an element whose
    `::after` you already style.

4. The jQuery API is preserved for the four behaviours, so `$(element).modal('show')`,
   `.tab('show')`, `.dropdown('toggle')` and `.collapse('hide')` need no change.
   `$(element).tooltip()` and `$(element).popover()` are now no-ops that return the
   collection rather than throwing, so existing calls are safe to leave in place but will
   do nothing. Popover has no replacement; tooltips move to the CSS-only `data-tooltip`.

5. Bootstrap's "already happened" events are emitted and reach both jQuery
   (`$(element).on('hidden.bs.modal', ...)`) and native listeners:

    - `shown.bs.modal`, `hidden.bs.modal`
    - `shown.bs.tab`

    The "about to happen" events — `show.bs.modal`, `hide.bs.modal`, `show.bs.tab` — are
    **not** emitted, and neither are any collapse or dropdown events. Code that depends on
    them, particularly to cancel an action with `preventDefault()`, needs reworking.

6. If your application binds `knockstrap`'s `carousel`, switch the import to
   `bindings/carousel`. The binding signature is unchanged:

    ```javascript
    import 'bindings/carousel';
    ```

    ```html
    <div data-bind="carousel: {content: {name: 'itemTemplate', data: images}}"></div>
    ```
