## Arches 8.2.0 Release Notes

### New Features

- Confirm support for Django 6.0 [#12584](https://github.com/archesproject/arches/pull/12584)
- Enable dynamic importing of TypeScript files [#12601](https://github.com/archesproject/arches/pull/12601)
- Move packages in arches-dev-dependencies repo into local peerDependencies [#12663](https://github.com/archesproject/arches/pull/12663)
- Move default configs from cards_x_nodes_x_widgets to node config [#12725](https://github.com/archesproject/arches/pull/12725)
- Add `--use_multiprocessing` (-mp) and `--max_subprocesses` (-mxp) options to the `etl` management command to control indexing parallelism, matching the `es` command [#PR](https://github.com/archesproject/arches/pull/PR)
- Extract sidenav into its own template for project-level customization [#12689](https://github.com/archesproject/arches/issues/12689)
- Datatypes can define their own copy logic when a resource or tile are cloned [#12706](https://github.com/archesproject/arches/pull/12706)
- During resource cloning, distinct resource_x_resource records are created for resource instance (list) nodes [#12715](https://github.com/archesproject/arches/pull/12715)
- Re-enable resource cloning in the resource editor and add copy-specify logic for edit-log display [#12749](https://github.com/archesproject/arches/pull/12749)
- Upgraded rdflib to 7.6.0 and Python 3.14 is now supported [#12790](https://github.com/archesproject/arches/pull/12790)
- Add command to calculate descriptors independent of ES index [#12828](https://github.com/archesproject/arches/issues/12828)
- Add option to forgo indexing during bulkload cli commands [#12883](https://github.com/archesproject/arches/pull/12883)
- Add method to filter resource queryset by permission [#12888](https://github.com/archesproject/arches/issues/12888)
- Add multi-card descriptor [#12829](https://github.com/archesproject/arches/pull/12829)
- Add Indonesian (`id`) UI locale [#12905](https://github.com/archesproject/arches/pull/12905)

- Reduce queries for published graphs when indexing [#11513](https://github.com/archesproject/arches/pull/11513)

- Improve memory management and performance in the bulk loader [#12767](https://github.com/archesproject/arches/pull/12767)

### Breaking changes

- The minimum supported version of Python is now 3.12.

- The `v3` migration management command is removed.

- The `FutureWarning` for missing `update_fields` in custom `update_or_create()` calls is removed. If you had `FutureWarning` in project tests on Arches 8.1, see the 8.1 release notes for a resolution.

- Bootstrap 3's JavaScript is no longer bundled; only its stylesheet is, vendored at `arches/app/media/css/vendor/bootstrap-3.4.1.css`. The modal, tab, dropdown and collapse plugins are reimplemented in `arches/app/media/js/bootstrap-behaviors/`, are installed automatically, and keep the `$(element).modal('show')` jQuery API, so existing call sites need no change.

    Tooltip and popover are not reimplemented: `$(element).tooltip()` and `$(element).popover()` are now no-ops rather than errors. If your project's markup uses `data-toggle="tooltip"` with `data-original-title`, those tooltips will silently stop appearing. Replace both attributes with a single `data-tooltip="..."` to use arches' CSS-only tooltip, which honors `data-placement="top"` and otherwise renders below the element. `data-container` is no longer meaningful and can be removed.

- The `datepicker` and `colorPicker` knockout bindings are now backed by Tempus Dominus 6 and a native `<input type="color">` respectively. Both keep their existing binding options, and the `format` and `viewMode` values stored in graph node configs are unchanged.

### Upgrading Arches

1. You must be upgraded to at least version 8.1.0 before proceeding. 

2. Upgrade to Arches 8.2.0
    ```
    pip install --upgrade arches==8.2.0
    ```

### Upgrading an Arches project

1. Follow instructions to upgrade each Arches project database to Postgres 16 or higher. https://www.postgresql.org/docs/current/upgrading.html

1. In pyproject.toml, make these updates:
    - Update `requires-python` to `">=3.12"`
    - Remove `"Programming Language :: Python :: 3.11"`
    - Remove `"Framework :: Django :: 5.2"`
    - Add `"Programming Language :: Python :: 3.14"`
    - Add `"Framework :: Django :: 6.0"`

1. Update ``EMAIL*`` settings to ``MAILERS`` following the [migration guide](https://docs.djangoproject.com/en/6.1/howto/mailers-migration/).

1. Optionally update settings to set `SECURE_REFERRER_POLICY = 'strict-origin-when-cross-origin'` to ensure referrer headers (strictly the origin) are sent in cross-origin HTTP requests. Resolves 404 errors from some map tile requests. For more details see [#12874](https://github.com/archesproject/arches/issues/12874).

1. Apply automatic updates:

    ```
    python manage.py updateproject
    ```

1. `updateproject` does not touch your project's templates. Because Arches no longer depends on Bootstrap 3, update `<project_name>/templates/index.htm` by hand.

    Replace the CDN stylesheet links with local equivalents:

    ```diff
    - <link rel="stylesheet" type="text/css" href="//fonts.googleapis.com/css?family=Open+Sans:400,300,600&amp;subset=cyrillic,latin">
    - <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/twitter-bootstrap/3.3.2/css/bootstrap.min.css">
    - <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/font-awesome/4.2.0/css/font-awesome.min.css">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'fonts/openSans.css' %}">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'css/vendor/bootstrap-3.4.1.css' %}">
    + <link rel="stylesheet" type="text/css" href="{% webpack_static 'node_modules/font-awesome/css/font-awesome.min.css' %}">
    ```

    Remove the Bootstrap script tag, which will 404 once `bootstrap` leaves `node_modules`:

    ```diff
    - <script src="{% webpack_static 'node_modules/bootstrap/dist/js/bootstrap.min.js' %}"></script>
    ```

    And load the replacement behaviours alongside the other bundles, so the landing page's navbar toggle keeps working:

    ```diff
      <!-- Custom Scripts -->
    + {% render_bundle 'bootstrap-behaviors/index' %}
      {% render_bundle 'bindings/chosen' %}
    ```

    If you have not customized `index.htm`, you can instead copy the current version from `arches/install/arches-templates/project_name/templates/index.htm`.

1. In package.json:

    Remove "arches-dev-dependencies" from "devDependencies" and run:


        ```bash
        rm -r node_modules; rm package-lock.json
        npm install
        ```

1. Migrate database:

    ```bash
    python manage.py migrate
    ```

1. Validate your graphs verify all default values are valid:

    ```bash
    python manage.py validate --verbosity=2
    ```
