# Upgrading Arches 7.6.x to 8.2.x

This guide consolidates the upgrade steps from the 8.0.0, 8.1.0 and 8.2.0
[release notes](../../releases) so a 7.6.x installation can move directly to 8.2.x
without stopping at 8.0 and 8.1. Refer to the individual release notes for the full
list of changes; this guide covers only what you must do.

> Back up your database before upgrading, as with any major upgrade.

## What changes

| | Your current 7.6.x install | After upgrading to 8.2.x |
| --- | --- | --- |
| Python | 3.10+ | **3.12+** (3.14 supported) |
| PostgreSQL | 14+ | **16+** (18 recommended) |
| Django | 4.2 | 6.1 (installed with Arches) |
| GDAL | | **3.3+** |
| GEOS | | **3.10+** |
| PostGIS | | **3.2+** (match your PostgreSQL version) |

GDAL, GEOS and PostGIS minimums are those of Django 6.1 ([GeoDjango libraries](https://docs.djangoproject.com/en/6.1/ref/contrib/gis/install/geolibs/)).

## Before you start

1. Upgrade to the latest 7.6.x release (8.0.0 requires at least 7.6.0; later patches contain more fixes).
1. Back up your database.
1. Upgrade PostgreSQL to 16+ with a matching PostGIS 3.2+ ([PostgreSQL docs](https://www.postgresql.org/docs/current/upgrading.html)).
1. Upgrade GDAL to 3.3+ and GEOS to 3.10+ using your OS package manager (e.g. `apt`, `brew`). GDAL 3.3–3.6 and GEOS 3.10–3.11 are supported by both 7.6.x and 8.2.x, so you can upgrade them before Arches. Newer versions are supported only by 8.2.x, so install those as part of the Arches upgrade.
1. If your Python is older than 3.12, install 3.12+ and create a new virtual environment with it.

## Upgrade Arches

```bash
pip install --upgrade pip
pip install --upgrade "arches>=8.2.0,<8.3.0"
```

(Use the latest 8.2.x patch release.) `psycopg2` is replaced by `psycopg` 3.x; any custom
code using `psycopg2` must be migrated
([differences from psycopg2](https://www.psycopg.org/psycopg3/docs/basic/from_pg2.html)).

## Upgrade your project

### 1. pyproject.toml

- `requires = ["setuptools>=77", "setuptools-scm"]`
- `requires-python = ">=3.12"`
- Update the arches dependency, e.g. `"arches>=8.2.0,<8.3.0"`.
- Classifiers: remove `Python :: 3.10`, `Python :: 3.11`, `Framework :: Django :: 4.2` and any `License :: ...`; add `Python :: 3.13`, `Python :: 3.14`, `Framework :: Django :: 6.1`.
- Replace `license = {text = "GNU AGPL3"}` with an SPDX string, e.g. `license = "AGPL-3.0-or-later"`.
- Rename `[project.optional-dependencies]` to `[dependency-groups]`.
- Unless already published to PyPI, use hyphens rather than underscores in `name`.

### 2. Housekeeping files

- `.gitignore`: remove `.tsconfig-paths.json` and `.frontend-configuration-settings.json`; add `frontend_configuration`, `build/` and `dist/`.
- `MANIFEST.in`: remove `graft *`; add exclusions for local settings, e.g. `exclude <my_project>/settings_local.py`.
- Replace `arches-project` management commands with `arches-admin` (`arches-project create` → `arches-admin startproject`).
- Delete `.frontend-configuration-settings.json`, `.tsconfig-paths.json` and `<project_name>/src/<project_name>/declarations.test.ts`.
- `tsconfig.json`: replace with `arches/install/arches-templates/tsconfig.json`. The 7.6 version extends `./.tsconfig-paths.json`, which is no longer generated, so `ts:check` (and therefore `npm run build_*`) fails until this is replaced.
- `vitest.setup.mts`: remove the `import '@/<project_name>/declarations.d.ts';` line (or copy the template).
- CI: copy `.github/actions/build-and-test-branch/action.yml` and `.github/workflows/main.yml` from `arches/install/arches-templates/.github/`, replacing `{{ project_name }}` in `main.yml`. The 7.6 action runs `pip install '.[dev]'`, which breaks after the `[dependency-groups]` rename, and its PostGIS image is too old.

> These steps were performed by the 8.0 `updateproject`, which 8.2's `updateproject` no longer includes.

### 3. settings.py

- `DATABASES["default"]`: add (for indexing performance)

    ```python
    "OPTIONS": {"options": "-c cursor_tuple_fraction=1"},
    ```

- `INSTALLED_APPS`:
    - Rename `"captcha"` to `"django_recaptcha"`.
    - Add `"django_migrate_sql"` and `"pgtrigger"` (before your project app).
    - Remove `"arches"` and `"django.contrib.admin"` from the first section, and make the trailing block:

        ```python
        INSTALLED_APPS += (
            "arches",
            "arches.app",
            "django.contrib.admin",
        )
        ```
- `LOGGING["loggers"]`: add `"django.request"` (handlers `["file", "console"]`, level `"WARNING"`, `propagate: True`) alongside `"arches"`.
- Remove `OVERRIDE_RESOURCE_MODEL_LOCK` if present.
- Replace `EMAIL*` settings with `MAILERS` per the [Django mailers migration guide](https://docs.djangoproject.com/en/6.1/howto/mailers-migration/).
- Optional: `SECURE_REFERRER_POLICY = "strict-origin-when-cross-origin"` (fixes 404s on some map tile requests).
- Rename `MAPBOX_SPRITES` / `MAPBOX_GLYPHS` to `MAPLIBRE_SPRITES` / `MAPLIBRE_GLYPHS` if you override them. `MAPBOX_API_KEY` is deprecated and no longer used (raises check warning `arches.W004`).
- If you override `DEFAULT_GEOCODER` or rely on the geocoder registry, see [Maps](#maps).

### 4. apps.py and urls.py

- `<project_name>/apps.py`: remove any `ready()` method and the `generate_frontend_configuration` import.
- `urls.py`: add the generic error handlers:

    ```python
    handler400 = "arches.app.views.main.custom_400"
    handler403 = "arches.app.views.main.custom_403"
    handler404 = "arches.app.views.main.custom_404"
    handler500 = "arches.app.views.main.custom_500"
    ```

### 5. Apply updates, migrate and publish

```bash
python manage.py updateproject
python manage.py migrate
python manage.py graph publish --update -ui
python manage.py check --deploy --settings=path.to.production.settings
python manage.py validate --verbosity=2
python manage.py es reindex_database
```

- `updateproject` deletes and recreates your `webpack/` and `vitest-utils/` directories, and replaces `eslint.config.mjs`, `vitest.config.mts` and `.github/dependabot.yml`. Back up any customizations to those first.
- `check --deploy` also generates the required frontend configuration.
- `validate --fix [error]` can repair issues found by `validate`; confirm all node default values are valid.
- If you copy client secrets from `/o/applications`, note they are now hashed. Save them before upgrading, or recreate the applications afterwards.

### 6. Frontend: package.json and source

- Point `"arches"` at the installed release, e.g. `"archesproject/arches#stable/8.2.0"` (match your installed 8.2.x version). **Remove** `arches-dev-dependencies` from `devDependencies`.
- Remove `NODE_OPTIONS` and `NODE_ENV` from scripts (`build_*`, `start`), e.g.
  `"build_development": "npm run eslint:check && npm run ts:check && cross-env webpack --config ./webpack/webpack.config.dev.js"`.
- Optional: make auto-fixers apply to staged files by default:
  `"eslint:fix": "eslint --fix"`, `"eslint:fix:all": "npm run eslint:fix **/src"`, `"prettier:fix": "prettier --write"`, `"prettier:fix:all": "npm run prettier:fix **/src"`.
- Replace PrimeVue with OpenVue: `"primevue"` → `"openvue": "1.0.0"`, `"@primeuix/themes"` → `"@openvue/themes": "1.0.0"`; in source, `primevue/*` → `openvue/*` and `@primevue/themes` / `@primeuix/themes` → `@openvue/themes`.
- Reinstall dependencies:

    ```bash
    rm -rf node_modules package-lock.json
    npm install
    ```

#### RequireJS removal (8.0.0)

Custom JavaScript must use ES modules:

- Replace `define([...], function(...) {...})` with `import` statements; whatever was `return`-ed becomes `export default`.
- Move any `require(...)` calls in function bodies to top-level imports.
- Custom knockout bindings: bind declared functions to the handler, e.g.
  `ko.bindingHandlers.hover.init = ko.bindingHandlers.hover.init.bind(ko.bindingHandlers.hover);`, then `export default ko.bindingHandlers.hover;`.
- Projects templated with `media/js/reports/default.js` can delete it unless it intentionally overrides core.

#### Templates

- Replace `{{ STATIC_URL }}path` with `{% webpack_static 'path' %}`.
- Components mounted from templates inheriting directly from `base-root.htm` no longer get the global `arches` object; use `generateArchesURL` and the settings API.
- `generateArchesURL()` URL names are now namespaced (8.1.0): `generateArchesURL("export_branch", ...)` → `generateArchesURL("arches:export_branch", ...)`. Valid names are the keys in `<project>/frontend_configuration/urls.json`.
- `arches.urls` is deprecated (optional): prefer `generateArchesURL`; once unused, delete `templates/arches_urls.htm`.
- `generateArchesURL`, `createVueApplication`, `ArchesPreset` and `DEFAULT_THEME` from `arches` are deprecated in favor of `arches-vue-components` equivalents.

#### index.htm (RequireJS and Bootstrap 3 JavaScript removed)

`updateproject` does not touch templates. A 7.6 `index.htm` loads its scripts through a RequireJS `require.config(...)` / `require([...])` block, which no longer works in 8.x.

The simplest fix is to copy `arches/install/arches-templates/project_name/templates/index.htm` over your `<project_name>/templates/index.htm`, replace `{{ project_name }}`, and re-apply any customizations.

If you edit by hand instead:

- Remove the `require.config(...)` / `require([...])` block. Load jQuery, underscore, knockout, chosen and the slider plugins with plain `<script src="{% webpack_static '...' %}">` tags. Load the Arches modules with `{% render_bundle %}`, and keep the `$(document).ready(...)` body in an inline `<script>`. Follow the bottom of the 8.2 template.
- Make these head and script changes:

```diff
- <link rel="stylesheet" type="text/css" href="//fonts.googleapis.com/css?family=Open+Sans:400,300,600&amp;subset=cyrillic,latin">
- <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/twitter-bootstrap/3.3.2/css/bootstrap.min.css">
- <link rel="stylesheet" type="text/css" href="//cdnjs.cloudflare.com/ajax/libs/font-awesome/4.2.0/css/font-awesome.min.css">
+ <link rel="stylesheet" type="text/css" href="{% webpack_static 'fonts/openSans.css' %}">
+ <link rel="stylesheet" type="text/css" href="{% webpack_static 'css/vendor/bootstrap-3.4.1.css' %}">
+ <link rel="stylesheet" type="text/css" href="{% webpack_static 'node_modules/font-awesome/css/font-awesome.min.css' %}">
  <!-- Custom Scripts -->
+ {% render_bundle 'bootstrap-behaviors/index' %}
+ {% render_bundle 'bindings/chosen' %}
+ {% render_bundle 'bindings/key-events-click' %}
+ {% render_bundle 'views/components/language-switcher' %}
```

Bootstrap behaviour changes:

- Modal, tab, dropdown and collapse (`data-toggle`, `data-dismiss="modal"`) work unchanged.
- Tooltip/popover are no-ops: replace `data-toggle="tooltip"` + `data-original-title` with `data-tooltip="..."`.
- `data-toggle="buttons"` and `data-dismiss="alert"` have no replacement.
- `bootstrap`, `bootstrap-colorpicker`, `eonasdan-bootstrap-datetimepicker` and `knockstrap` are gone; remove them from your `package.json` and `nodeModulesPaths`. The `datepicker` and `colorPicker` bindings keep their options.

#### Maps

- `bindings/mapbox-gl` → `bindings/maplibre-gl`, `mapboxgl` binding → `maplibregl`, `.mapboxgl-*` → `.maplibregl-*`. `@mapbox/mapbox-gl-draw` is unaffected.
- The `Geocoder` model, `DEFAULT_GEOCODER`, the `mapbox`/`base-geocoder` components and `arches.geocodingProviders` / `geocoderDefault` / `mapboxApiKey` JS values are removed. The geocoder defaults to OpenStreetMap Nominatim; to change it, override `arches/app/media/js/utils/maplibre-geocoder-api.js` (and its `geocoderAttribution`).
- The default `satellite` basemap is removed.

### 7. Optional: bundled applications (8.2.0)

`arches_querysets`, `arches_vue_components` and `arches_controlled_lists` now ship inside Arches as `arches.extensions.querysets`, `.vue_components` and `.controlled_lists`. Enabling is optional for existing projects; see
[Applications Bundled with Arches](https://arches.readthedocs.io/en/stable/developing/extension-applications/bundled-applications/) and the 8.2.0 release notes for the full settings, `CACHES`, Elasticsearch index and `urls.py` steps. Notes:

- If you pip-installed them separately, `pip uninstall arches-querysets arches-vue-components arches-controlled-lists` first. Old top-level module paths still work in 8.2 with a `DeprecationWarning` and are removed in 9.0.
- Enabling `arches.extensions.querysets` overrides several core datatypes (`file-list`, `concept`, `resource-instance`, `string`, `url`, etc.) project-wide.
- If enabling `controlled_lists`, run `python manage.py es setup_indexes -n references`.

### 8. Build

```bash
npm start                  # development with live rebuild
npm run build_development  # development build with checks
npm run build_production   # production
python manage.py collectstatic  # production / non-local
```

Restart Apache (`sudo service apache2 reload`) if applicable.

## Breaking changes for custom code

### Python / ORM

- `TileModel.nodegroup` FK constraint is no longer enforced; `TileModel.nodegroup` and `LoadStaging.nodegroup` are now nullable.
- No longer nullable (set explicitly in custom SQL or ORM calls that bypass `save()`): `Node.alias`, `Node.graph`, `TileModel.data`, `Graph.slug`.
- `ResourceXResource` fields renamed (columns unchanged): `resourceinstanceidfrom` → `from_resource`, `resourceinstanceidto` → `to_resource`, `resourceinstancefrom_graphid` → `from_resource_graph`, `resourceinstanceto_graphid` → `to_resource_graph`, `nodeid` → `node`, `tileid` → `tile`. `datestarted` and `dateended` are removed. The `.relations` importer accepts only the new headers.
- New `related_name`s:
    - NodeGroup: `nodegroup` → `child`, `nodegroup_set` → `children`, `tilemodel` → `tile`, `tilemodel_set` → `tiles`.
    - TileModel: `tilemodel` → `child`, `tilemodel_set` → `children`.
    - ResourceInstance: `resxres_resource_instance_ids_from` → `from_resxres`, `resxres_resource_instance_ids_to` → `to_resxres`.
    - Graph: `resxres_resource_instance_fom_graph_id` → `from_resxres`, `resxres_resource_instance_to_graph_id` → `to_resxres`.
    - Node: `resxres_node_id` → `resxres`.
- Default ordering by `sortorder` (`helpsortorder` for ETLModule) on `CardModel`/`Card`, `CardXNodeXWidget`, `Node`, `Plugin`, `ETLModule`; use an empty `order_by()` to opt out.
- Tile cardinality errors raise `TileCardinalityError` (not `ProgrammingError`); `TileValidationError` and `TileCardinalityError` subclass `django.core.exceptions.ValidationError`. Tile functions no longer catch `TypeError`.
- `GraphModel.get_published_graph()` no longer accepts `raise_if_missing`; `Graph.new()` is deprecated for `Graph.objects.create_graph()`; `ensure_userprofile_exists()` removed from `Tile`.
- `WorkflowHistoryView` moved to `arches.app.views.api`.
- `arches.VERSION` is removed; use `arches.__version__` (parse with `packaging.version.Version`).
- `manage.py packages -o install`, `arches-project` commands and the `v3` migration command are removed.
- `update_or_create()` no longer injects `save()`-computed fields silently; 8.1 raised `FutureWarning` (removed in 8.2). If you saw it, add the fields you need (e.g. `sortorder`) to `defaults`.
- `Resource.copy()` now requires `context` to be a dict.
- django-oauth-toolkit 3.x: client secrets are hashed.

### Frontend

- RequireJS, PrimeVue (→ OpenVue), Bootstrap 3 JS and Mapbox GL JS (→ MapLibre) are removed; see above.
- `.mapboxgl-*` CSS classes and `knockstrap` bindings no longer exist.

## Notable fixes in 8.0.x / 8.1.x (included in 8.2.x)

No action required; included for awareness.

- 8.0.7: **security** fix for default-deny permissions API access. 8.0.9 and 8.0.10 also roll in the 7.6.21 and 7.6.22 fixes.
- 8.1.0: default-deny permission framework for *new* projects only; new `Language` datatype; `ResourceIdentifier` model/API; users loadable from packages; bulk-import metadata and local-storage file upload.
- 8.1.3: nodegroup permissions no longer reset when a Graph is initialized; Vue/webpack build fixes. 8.1.4: `globals` npm package added for ESLint.

## Dependency summary

- **Python added:** `django-pgtrigger`, `django-sql-migrate-deux`, `djangorestframework`, `packaging`, `psycopg` 3.x. **Removed:** `psycopg2`, `pytz`, `tomli`.
- **Python upgraded (selected):** Django (5.2 → 6.x), celery 5.5, django-oauth-toolkit 3.4, elasticsearch 8.19, pillow 11.3, rdflib 7.6.
- **JavaScript added:** `maplibre-gl`, `@maplibre/maplibre-gl-geocoder`, `@eonasdan/tempus-dominus`, `openvue`, `@openvue/themes`, `primeicons`. **Removed:** `requirejs*`, `regenerator-runtime`, `bootstrap*`, `knockstrap`, `eonasdan-bootstrap-datetimepicker`, `mapbox-gl`, `@mapbox/mapbox-gl-geocoder`, `primevue`, `@primeuix/themes`, `copy-webpack-plugin`.
- See the release notes for exact versions.
