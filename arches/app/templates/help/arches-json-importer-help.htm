{% trans "Import Arches JSON" %}

{% blocktrans %}Bulk import of Arches JSON business data, built for large loads. Upload a .json Arches business-data export, a .jsonl file with one resource object per line, or a .zip of either.{% endblocktrans %}

{% blocktrans %}Prefer .jsonl for very large loads: it streams, whereas a .json file is parsed whole. To convert an existing export:{% endblocktrans %} 

jq -c '.business_data.resources[]' export.json > export.jsonl

{% blocktrans %}The file is read twice: once to validate every resource, once to write. Nothing is written if validation turns up any error, so a failed load leaves the database untouched. Failures appear in the standard error report.{% endblocktrans %}

{% blocktrans %}Tick Overwrite resources that already exist to replace resources whose ids are already in the database. Left unticked, importing a resource id that is already present will fail the load.{% endblocktrans %}

{% blocktrans %}Untick Index the data after import to write the tiles without indexing them. The data is saved but will not appear in search until you run python manage.py index_database. Useful when loading several files in a row: skip indexing on each and index once at the end.{% endblocktrans %}

{% trans "Importing from the command line" %}

{% blocktrans %}The same importer runs from the command line, which is the better route for very large loads: it reports progress as it validates, and it is the only path that can index across several processes.{% endblocktrans %} 

python manage.py etl arches-json-importer -s /path/to/export.jsonl

{% trans "Flags:" %}

  • -s, --source — {% trans "the .json, .jsonl or .zip file to load. Required." %}
  • -o, --overwrite — {% trans "replace resources that already exist instead of failing on them." %}
  • --no-index — {% trans "write the data but skip indexing; reindex later with index_database." %}
  • -mp, --use_multiprocessing — {% trans "index across several processes after loading." %}
  • -mxp N, --max_subprocesses N — {% trans "how many processes to index with. Defaults to half the CPU count." %}
  • -c, --config — {% trans "a JSON file of options. The flags above win over it." %}

{% blocktrans %}A large overnight load, overwriting existing resources and indexing on eight processes:{% endblocktrans %} 

python manage.py etl arches-json-importer -s export.jsonl -o -mp -mxp 8

{% blocktrans %}Multiprocessed indexing is deliberately not offered in the panel above. A load larger than the module's size limit is handed to a Celery worker, whose processes cannot themselves start child processes, so a pool there would leave the data written but never indexed. Use the command line when you want indexing spread across cores.{% endblocktrans %}
